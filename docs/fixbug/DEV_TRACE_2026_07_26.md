## 18. Kết luận

1. **Backend pipeline chạy đúng hay sai?** — Backend pipeline chạy ĐÚNG. Toàn bộ các bước Controller → WorkflowService → Orchestrator → Dispatcher → claudeCodeRunner → SDK → Validator đều đi qua đúng thứ tự. Validator chạy đúng (phát hiện đúng 3 key thiếu). Task failure transition đúng (status=failed, executionStatus=failed). DB row đúng shape. Stack trace đúng.

2. **Claude chết ở bước nào?** — Claude KHÔNG chết. Claude CLI subprocess thoát cleanly lúc 10:27:08.223 (25 s sau turn cuối, không có SIGTERM, không có timeout hit, không có signal). Run này fail ở bước Validator contract check (`claudeCodeRunner.js:353` `assertOutputConforms`, throw tại line 363), không phải ở bước SDK. Lý do: Claude chỉ gọi Bash ×3 + Read ×3 (không có Write/Edit/MultiEdit), không phát ra JSON contract envelope chứa `implementation_plan`/`patch_diff`/`changed_files`. Đây là một failure mode hoàn toàn khác với failure `exit code 143` quan sát trong session `93c8f0cd…` trước đó.

3. **Root cause đã được CHỨNG MINH hay CHƯA?** — KHÔNG ĐỦ EVIDENCE ĐỂ KẾT LUẬN cho failure `exit code 143` ban đầu. Run này KHÔNG tái hiện được lỗi đó — Claude không gặp 143, mà gặp `CLAUDE_OUTPUT_CONTRACT_INVALID` (một failure mode khác, do validator backend phát hiện). Để chứng minh root cause của exit 143, cần một run mới với input khiến Claude thực sự viết code (`frontend/src/App.jsx`, `frontend/src/App.css`) thay vì chỉ đọc — vì trong session fail gốc, Claude đã viết code nhưng rồi iterator chưa kết thúc. Cần tăng `CLAUDE_CODE_DEV_MAX_TURNS` lên ≥ 200 và không ép `CLAUDE_CODE_TIMEOUT_MS` thấp, để Claude có cơ hội hoàn thành + emit JSON contract trước khi process bị parent Node kill.
