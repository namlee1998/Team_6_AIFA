# T8 — final.md 10-section template (B9)

## Goal
Spec §13 final.md mandates 10 mandatory sections. The previous
`buildFinalMarkdown` produced 8 sections (Feature, PO, UX, DEV, QA,
Release Evidence, Audit Trail, Release Decision) and was missing the
spec-required Repository, ARCH Output, Human Decisions, and a
human-readable Pipeline Summary.

## Approach
1. Rewrote `buildFinalMarkdown` in `workflowReport.js` to render the 10
   spec §13 sections, in order, **unconditionally** (each falls back to
   `_none_` when data is absent so the format stays stable for any
   downstream consumer / PR template).
2. New signature adds `session` and `repoContext` so Repository and
   Pipeline Summary can render real values.
3. DEV diff prefers the live git `diff` arg; falls back to the
   `dev-agent.patch_diff` artifact captured at approve time when no
   repo clone is available (back-compat with the prior test).
4. Pipeline Summary computes wall-clock duration from the audit trail
   start and the final `releaseDecision.createdAt`.

## Files changed
- `backend/src/services/workflowReport.js` — `buildFinalMarkdown`
  rewritten with the 10 spec sections; `writeReleaseBundle` passes
  `session` and `repoContext` through.
- `backend/tests/integration/workflow-report.test.js` — existing test
  updated to the new section names; new "renders all 10 sections" test
  added; mock widened with `repoPathFor` + `slugify` so the bundle
  writer can resolve its output directory in CI.

## Sections produced (in order)
1. Repository — URL / base branch / working branch / commit SHA (7-char)
2. Feature Request — original user string (not the parsed JSON)
3. ARCH Output (architecture.md) — full `architecture_brief`
4. PO Output (product-spec.md) — `prd` + `acceptance_criteria`
5. UX Output (ux-design.md) — `ux_spec`
6. DEV Output (diff + file list) — changed-files + diff (≤8000 chars)
7. QA Output (qa-report.md) — `qa_report` + `test_run_report` + `ac_coverage_matrix`
8. Audit Trail — `AgentEvents` sorted ascending by timestamp
9. Human Decisions — clarification Q&A + every approve/reject decision
10. Pipeline Summary — wall-clock duration, commit count, final status

(The legacy "Release Evidence (raw)" JSON block is preserved at the end
for back-compat with any consumer that still parses it.)

## Decisions captured
- Pipeline Summary uses `commit ` lines from the diff to count commits
  (each approved agent appends one commit per spec §11) — this is
  more accurate than counting files.
- Sections render even with empty data (`_none_`) rather than being
  omitted — keeps the format stable for downstream automation / PR
  templates that grep for section names.
- The "Release Evidence (raw)" block is preserved and labelled so
  consumers can still grab the JSON view if needed.
