# T2 — Human Question shape fix (B1)

## Goal
Frontend ClarificationPanel + spec §6.1 expect `clarification_questions` as
`{question, header?, options?}[]`. Backend was producing `string[]`, so the
panel rendered empty (no `firstQ.question`, no options).

## Approach
Per user decision: update ALL three prompts to object form (ARCH, PO, UX),
plus add a defensive backend normalizer so any agent still emitting the
old `string[]` form during migration doesn't crash.

## Files changed
- `backend/src/agents/prompts/po.prompt.md`: `clarification_questions` now
  documented as `[{question, header, options}]` with 2–4 options, header
  max 12 chars.
- `backend/src/agents/prompts/architecture.prompt.md`: same.
- `backend/src/agents/prompts/ux.prompt.md`: same, with example object.
- `backend/src/services/agentContract.js`: new exported helper
  `normalizeClarificationQuestions(raw, {logger})` — coerces string[],
  partial objects, mixed arrays; never throws; warns on items missing
  question text. 7 unit tests added.
- `backend/src/services/SdlcWorkflowService.js`: import the helper, call it
  at the gate creation site (~line 1854) and pass `normalizedQuestions` as
  the gate payload. Old site kept the same `if (Array.isArray(...) && .length > 0)`
  guard by swapping the variable.
- `frontend/src/services/api/sdlcApi.ts`:
  - `GateType` union expanded to include `UX_CLARIFY`, `DEV_CLARIFY`,
    `QA_CLARIFY`, `AGENT_CLARIFY` (only `PO_CLARIFY` was there before).
  - `GateItem.payload.questions` type changed from `string[]` to
    `ClarificationQuestion[]` (new exported interface).
- `frontend/src/pages/SdlcDashboard/components/ClarificationPanel.tsx`:
  removed local `QuestionDef` (duplicate of API type), imports
  `ClarificationQuestion`, drops the unsafe `as unknown as` cast.
- `frontend/src/pages/SdlcDashboard/index.tsx`: clarification auto-jump now
  matches all 5 clarification types (`PO/UX/DEV/QA/AGENT_CLARIFY`).
- `frontend/src/pages/SdlcDashboard/components/InspectorPanel.tsx`: same
  widening (auto-jump, badge count, panel render condition).

## Decisions captured
- Q (user): update ALL prompts vs normalize-only backend → user picked
  "Update tất cả: ARCH + PO + UX prompts" so output is consistent across agents.
- Backend normalize is kept as a safety net (defense-in-depth), not as the
  primary migration path.
- Legacy `sdlcLegacy.ts` `PO_CLARIFY`-only mappings are intentionally left
  untouched (out of scope; touches dead code). Workflow selectors and
  OverviewPage keep the PO-only label (PO is the dominant clarification
  agent; widening there was not required for B1 acceptance).
