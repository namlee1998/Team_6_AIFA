# T4 — Remove AuditPage duplicate (B3)

## Goal
Spec §8.2: "Không còn Audit page riêng. Runtime Log chính là timeline duy
nhất — mọi AgentEvent (bắt đầu step, gọi tool, ghi file, lỗi, hoàn tất)
đều xuất hiện tuần tự tại đây." Stop condition from user: "auditLog chứa
dữ liệu không thể migrate an toàn" → keep the model field for backward
compat, stop using it as a render source.

## Approach
- Delete the AuditPage route + sidebar link + dashboard header link.
- Old `/sdlc/audit` URLs redirect to `/sdlc/build` so existing bookmarks
  don't 404.
- Timeline selector now reads `runtimeEvents` only (no fallback to `auditLog`).

## Files changed
- `frontend/src/pages/SdlcDashboard/AuditPage.tsx`: DELETED.
- `frontend/src/components/layout/AppShell.tsx`: removed lazy import of
  AuditPage; removed `isAuditRoute` branch (renamed to `isLegacyAuditRoute`
  for clarity); added redirect via `navigate('/sdlc/build', {replace:true})`
  for old audit URLs.
- `frontend/src/components/layout/AppSidebar.tsx`: removed the "Audit Logs"
  button + `isAuditActive` flag + unused `History` icon import.
- `frontend/src/pages/SdlcDashboard/index.tsx`: removed the "Audit trail"
  header button + unused `FileText` icon import.
- `frontend/src/store/workflowSelectors.ts`: removed `timelineFromAudit()`
  dead helper; changed `selectRuntimeExecution` to read only
  `runtimeEvents` (no audit fallback). Comment explains why.

## What was NOT changed
- `SessionState.auditLog` and `api.AuditEntry[]` types stay in place —
  removing them would invalidate stored sessions. New sessions simply
  accumulate events into `runtimeEvents` instead.
- `useWorkflowStore` still has the `_applySseEvent` arm that merges
  `data.auditLog` if the backend ever sends it; that's harmless.

## Decisions captured
- Old bookmarks should not 404 → redirect to /sdlc/build.
- Removed "Audit Logs" sidebar button entirely (not greyed-out / disabled),
  because the spec is unambiguous about removing the surface.
