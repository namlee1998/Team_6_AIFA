# T7 — Session Summary fields + dynamic task list (B7)

## Goal
Spec §8.1 mandates the Session Summary panel render these 5 fields:
- Repository · Branch · Commit SHA · Pipeline Status · Current Agent

Plus dashboard cards: Completed Agents · Generated Files · Errors · Warnings.

Pre-T7: `SessionSummaryBar` only showed featureRequest, sessionId slice,
completed/5, currentAgent, and gateCount. `repoInfo` was an empty stub
on the backend (no branch / SHA). The "task list" was already derived
from `pipelinePhases` per-agent, so the dynamic-derivation requirement
was already met — but the summary line that wraps that data was
spec-noncompliant.

## Approach
Backend side (data source):
1. New `repoService.getSessionRepoInfo({projectId, sessionId})` —
   best-effort git plumbing: `rev-parse --abbrev-ref HEAD`,
   `rev-parse --short HEAD`, `git ls-files | wc -l`. Never throws;
   returns `null` if the workspace isn't initialised yet (early race).
2. `SdlcWorkflowService._buildSessionRepoInfo({projectId, sessionId})`
   composes the API shape and is called from `getPipelineResponse`.
   The legacy `techStack`/`components` fields are dropped (vestigial).
3. `repoUrl` stays on the frontend session seed (it's transient input
   passed at startPipeline, not persisted on PipelineSession).

Frontend side (render):
1. `frontend/src/services/api/sdlcApi.ts` — `repoInfo` type now
   includes `repoUrl?`, `branch?`, `commitSha?`, `fileCount?`. Legacy
   `techStack`/`components` kept optional for back-compat.
2. `frontend/src/pages/SdlcDashboard/index.tsx` — `SessionSummaryBar`
   rewritten to render:
   - Top row: 5 spec fields as compact label/code pairs.
   - Bottom row: 4 dashboard cards (Completed / Files / Errors / Warnings).
   - Error/warning counts derived from `runtimeEvents[type=error]` +
     `session.error` and `gateHistory[decision=reject]` respectively.

## Files changed

## Decisions captured
- "Generated Files" uses `git ls-files` count (not a feature list) —
  the spec says "Generated Files" plural and the count is what the
  Session Summary actually needs.
- "Errors" merges runtime `error` events with `session.error` (the
  terminal pipeline error) — both are error conditions the operator
  needs to see in one place.
- "Warnings" maps to rejected gates (a non-fatal-but-noteworthy signal
  that the operator should glance at).
- The compact SHA is sliced to 7 chars (industry convention).
- Branch name is shown as-is; long branch names wrap on mobile.
