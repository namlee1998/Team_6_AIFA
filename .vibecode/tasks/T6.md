# T6 — agent_event envelope `type` at root (B8)

## Goal
Spec §11 puts the envelope `type` at the **root** of every `agent_event`
SSE message (not nested under `payload`). The store was reading
`data.type` correctly but ALSO had a silent fallback to
`'agent_tool_call'` whenever the type was missing/unknown — masking real
type values like `gate_audit` (which the backend DOES emit but the
frontend `RuntimeEventType` union does NOT contain). On the wire the
data is fine; the bug is purely the silent coercion in the store.

## Approach
1. Backend confirmed: `SdlcController.flushPersistedEvents` re-emits
   `ev.type` at root → no backend change required (the wire was always
   correct).
2. Frontend: validate `data.type` against the known `RuntimeEventType`
   union, log a `console.warn` on unknown values, fall back to
   `agent_tool_call` ONLY when type is missing/invalid (not when it is
   a known-but-unlisted backend type). Diagnostic on every fallback so
   regressions show up in DevTools instead of corrupting the timeline.

## Files changed
- `frontend/src/store/useWorkflowStore.ts` — `agent_event` branch now:
  - Builds an explicit `knownTypes` set from the 9-type union.
  - Reads `incomingType` strictly (`typeof string`).
  - Resolves via set membership; logs warn on unknown strings instead
    of silently overwriting with `'agent_tool_call'`.

## Decisions captured
- Did NOT add `gate_audit` to the union: it's a backend-only audit row,
  not a timeline event. The Timeline panel correctly renders audit
  events from `auditLog`, not `runtimeEvents`. Keeping them separate
  preserves the spec §8.2 model ("runtime log is one timeline, audit
  is separate").
- Kept the `agent_tool_call` fallback for genuinely-missing `type`
  fields so the UI never crashes on a partial wire packet — but only
  when the field is absent/invalid, never when it's an unknown string.
