# T1 — Auto commit+push on Approve (B5/B10)

## Goal
Spec §7.2: Approving an Output Review gate must drive `add → commit → push`
before waking the next agent. Without this, agent output stays in the DB
without ever landing in the repo, and a "successful" run leaves no trace.

## Approach (per user decision Q1+Q2)
- Extract `commitAndPushOnApprove({task, onLog})` into `repoService.js` (NOT
  inline in `resolveOutputReviewGate`) so AgentOutputPanel's manual Sync/Commit/
  Push buttons can reuse the same helper later. Reuses existing `git()`,
  `repoPathFor()`, `commitAndDiff()` patterns.
- `add` + `commit`: mandatory, can throw into caller (would surface as a 500
  and the gate stays in `awaiting_gate` state — the operator must retry).
- `push`: best-effort. `process.env.GH_TOKEN` is the only source (no token is
  stored on the session). Failures are returned in `result.pushError` and
  pushed to the frontend via `gateBridge.emit(taskId, 'runtime_log', ...)`,
  never silently dropped. Push NEVER blocks the pipeline — a network/auth
  failure must not undo the commit or stall the next agent.

## Commit message format (spec §7.1)
`[<agent-tag>][<run-id>] <description>` where:
- `<agent-tag>` = sanitized `task.type` (e.g. `dev-agent` → `dev-agent`)
- `<run-id>` = first 8 chars of `task.id` + `outputVersion`
- `<description>` = first non-empty heading line from
  `agentOutput.{summary,title,subject,prd,ux_spec,implementation_plan}`, capped
  at 72 chars.

## Files changed
- `backend/src/services/repoService.js`: added `commitAndPushOnApprove()`,
  `deriveCommitDescription()`, exported the new helper.
- `backend/src/services/SdlcWorkflowService.js`: in `resolveOutputReviewGate`
  approve branch, call `repoService.commitAndPushOnApprove({task, onLog})`
  after `AgentArtifact.setStatusByTaskId(task.id, 'VALID')` and before
  `_startNextAgentIfAvailable`. `onLog` writes to
  `gateBridge.emit(taskId, 'runtime_log', {level, source, message, meta})`.
